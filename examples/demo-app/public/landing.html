Build time — runs in your CI, code never leaves

Three passes, each one checkable on its own

L1 — AST scan

Facts only. No interpretation, no LLM.

Walks app/ and pages/, finds every button, link, form and input, traces each handler to the API call it makes. Same source in, byte-identical output out — the determinism check runs on every push.

ts-morph · deterministic

L2 — reachability

Finds what's dead. Adjudicates what's duplicated.

Walks the import graph from every route. Unreached files are flagged dead. When two components share a name, scores them on reachability, inbound imports, and recency — and records why.

graph walk · deterministic

L3 — describe

The only pass that calls an LLM.

Writes a concrete purpose, whenToUse, and does for every page and element — cached by content hash, so a warm build with no relevant changes never calls the model again. Bring your own key: Anthropic or Groq.

cached · your API key

Run time — your browser, your server, your auth

The model never touches code. Only a verb.

Every response is forced into one of five verbs — explain, highlight, open, navigate, do — and re-validated server-side against that exact schema. Anything else, including a prompt-injection attempt, is rejected before it reaches the page.

01

Fixed verb enum

The LLM never emits a selector or code — only one of five verbs, schema-checked twice.

02

Element ladder

data-ai → aria-label → visible text → fail. A miss degrades to explain, never a wrong click.

03

Deterministic build

L1 and L2 are pure functions. The same commit always produces the same manifest.

04

Your auth, not ours

The do verb runs through your own session and your registered action list — never a service key.
