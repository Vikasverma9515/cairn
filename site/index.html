In plain English

What Cairn actually does

Normally, using new software means learning it — where the buttons are, what they're called, which order to click them in. Cairn flips that around. You describe what you want, out loud or typed, and the agent does it — using the app's real buttons and real actions, the same way you would with a mouse. Say "build me a flow that emails me on a new lead," and it happens in front of you, in a tool you've never opened before.

Vibe coding is describing the app you want built. This is vibe using — describing what you want done. It's not a chatbot bolted onto the side that tells you what to click. It clicks.

For your customers

They don't learn your product. They say what they want and watch it happen in real time — talked or typed, no manual, no support ticket.

For you, the builder

Every user gets a product expert without you writing an onboarding flow — Cairn reads your source once and already knows what your app can do.

For your peace of mind

The agent can only take actions you've explicitly registered, checked server-side against a fixed list — it can never invent a click or run arbitrary code.

How it works

Cairn reads your app once, then acts inside it, live.

Everything except the description-writing step is plain static analysis — same input, same output, every time. The agent doesn't improvise a UI it's never seen; it works from a real map of your app's actual buttons, forms, and actions.

01 · deterministic

Read the source

Every route, component, and handler — the same way a new hire would learn your app.

02 · deterministic

Map what's real

What's actually wired up and clickable, not just declared somewhere in the code.

03 · one-time

Register the actions

You expose the write actions you want the agent to be able to take — archive an invoice, add a workflow step — through your own auth.

04 · live

Talk, and it acts

A customer describes what they want; the agent explains, highlights, navigates, or does it — through the real UI, in real time.

What keeps it safe

The model never picks a selector. It picks one of five verbs.

Every response is independently re-validated server-side against a fixed schema — regardless of what the client sends. It can only take an action you registered; it can never invent a click, run arbitrary code, or touch something you didn't allow. A lookup miss degrades to a plain explanation, never a guess.

Features

Everything a "someone else uses it for you" agent needs.

Streaming voice

A persistent WebSocket, not a buffered clip — audio starts in ~1–1.5s instead of a 5–10s wait. Talk over it mid-sentence and it stops immediately (barge-in).

Multi-step walkthroughs

A request that spans several steps comes back as an ordered sequence — highlight, narrate, act, move on — not one paragraph naming five buttons at once.

Any framework, any stack

React via <Copilot/>, or drop <cairn-widget> into Vue, Angular, Svelte, or a plain static HTML page — same web component, zero dependencies.

Works on apps you didn't write

Point cairn build at a running URL instead of source and it crawls the rendered page with a headless browser — works on any framework's output.

Conversation memory

"Do that for the other one too" resolves against the last few turns, not just the current request — a real back-and-forth, not stateless Q&A.

Capability tiers

explain / guide / act caps what the agent is allowed to do, independent of which actions your app has registered — dial it up per customer, per plan.

Install

Wire it into your app in about ten minutes.

Next.js is the only framework the source-reading analyzer understands today — the runtime (voice, action execution, element finding) is already framework-agnostic, and crawl mode covers everything else in the meantime.

Not published to npm yet — install via a file: path pointing at a local clone (below), or as a git dependency, until it is.
bash
# 1. clone and build the CLI + SDK once
git clone https://github.com/Vikasverma9515/cairn.git
cd cairn && npm install
npm run build -w @cairn/indexer -w @cairn/sdk
npm install                # re-run so npm links the cairn / cairn-realtime bins

# 2. point it at your Next.js app
cp .env.example .env       # fill in ANTHROPIC_API_KEY or GROQ_API_KEYS
npx cairn build ./your-app --provider groq

# 3. register the actions the agent can take, mount the widget
npx cairn init ./your-app   # scaffolds the backend route + .env.example

CLI reference

Six commands, that's the whole surface.

CommandWhat it does
cairn init <dir>Scaffolds the backend route + .env.example — detects your framework, never overwrites existing files.
cairn scan <dir>L1 only — deterministic, no LLM call, no API key needed.
cairn build <dir>Full pipeline against Next.js source — writes ui-manifest.json.
cairn build <url>Crawl mode — points at a running app instead of source, works on any framework.
cairn diff <a> <b>What changed between two manifests — useful in CI to catch silent drift.
cairn docs <dir>Reads an existing manifest and writes a human-readable CAIRN_DOCS.md.
